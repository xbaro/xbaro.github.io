# _memory — structured content memory (not published)

Source of truth for the site's reference content (publications now; talks, teaching, projects later).
Directories starting with `_` are not copied to the generated site by Jekyll, so nothing here is served at xbaro.eu.
The repository itself is **public**: store only information that is already public.

| File | Purpose |
|---|---|
| `references.json` | Merged, canonical references (generated by `sync`; do not edit by hand) |
| `overrides.json` | Manual corrections keyed by reference `id`; applied after every sync (e.g. `"status": "rejected"`) |
| `sources/` | Cached raw responses (ORCID, OpenAlex) and publications/talks extracted from the owner's CV (`cv_publications.json`, `cv_talks.json`), plus the owner's Google Scholar profile exported manually as BibTeX (`scholar.bib`) |
| `index.sqlite` | Full-text search index (derived, git-ignored) |
| `tools/memory.py` | CLI, run with `uv` |

## Status
- `confirmed` — listed in the owner's ORCID record, CV or Google Scholar profile.
- `candidate` — found in OpenAlex only; needs review (accept → set `"status": "confirmed"`, or `"rejected"` in `overrides.json`).
- `rejected` — not authored by the owner; kept so sync never re-proposes it.

## Update flow
```bash
uv run _memory/tools/memory.py sync            # fetch ORCID + OpenAlex, merge, reindex
uv run _memory/tools/memory.py search "gesture recognition"
uv run _memory/tools/memory.py stats
```
CV import (publications + talks only; personal data in the CV is never copied; the CV file itself is NOT stored in the repo):
```bash
uv run _memory/tools/memory.py import-cv /path/to/CV.docx && uv run _memory/tools/memory.py sync --offline
```
Google Scholar blocks automated access: to refresh it, export the profile (Select all → Export → BibTeX) over `sources/scholar.bib` and run `sync --offline`.

Sources: Google Scholar (manual export), CV (AQU normalised format, 2024-12-31), ORCID `0000-0001-5338-3007` (public API), OpenAlex (public API, no key; paging via `page=`).
