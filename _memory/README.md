# _memory — structured content memory (not published)

Source of truth for the site's reference content (publications now; talks, teaching, projects later).
Directories starting with `_` are not copied to the generated site by Jekyll, so nothing here is served at xbaro.eu.
The repository itself is **public**: store only information that is already public.

| File | Purpose |
|---|---|
| `references.json` | Merged, canonical references (generated by `sync`; do not edit by hand) |
| `overrides.json` | Manual corrections keyed by reference `id`; applied after every sync (e.g. `"status": "rejected"`) |
| `sources/` | Cached raw responses (ORCID, OpenAlex) and publications/talks extracted from the owner's CV (`cv_publications.json`, `cv_talks.json`), plus the owner's Google Scholar profile exported manually as BibTeX (`scholar.bib`) |
| `references.bib` | Canonical BibTeX (UTF-8) of all `confirmed` references, regenerated by `sync`/`bib`; kept in the repo to ease export and reuse |
| `metrics.json` | Citations and journal indicators per reference (generated by `metrics`; merged into `references.json` as `metrics`) |
| `theses.json` | Theses from the Portal de la Recerca de Catalunya: the owner's own (2009) and the four co-directed ones (for a future supervision section; generated by `portal`/`sync`) |
| `index.sqlite` | Full-text search index (derived, git-ignored) |
| `tools/memory.py` | CLI, run with `uv` |

## Status
- `confirmed` — listed in the owner's ORCID record, CV or Google Scholar profile.
- `candidate` — found in OpenAlex only; needs review (accept → set `"status": "confirmed"`, or `"rejected"` in `overrides.json`).
- `duplicate` — preprint/earlier version of another reference (`duplicate_of` gives the canonical id); kept for traceability, not shown.
- `rejected` — not authored by the owner; kept so sync never re-proposes it.

## Update flow
```bash
uv run _memory/tools/memory.py sync            # fetch ORCID + OpenAlex, merge, reindex
uv run _memory/tools/memory.py search "gesture recognition"
uv run _memory/tools/memory.py stats
```
CV import (publications + talks only; personal data in the CV is never copied; the CV file itself is NOT stored in the repo):
```bash
uv run _memory/tools/memory.py import-cv /path/to/CV.docx && uv run _memory/tools/memory.py sync --offline
```
Google Scholar blocks automated access: to refresh it, export the profile (Select all → Export → BibTeX) over `sources/scholar.bib` and run `sync --offline`.

Sources: Google Scholar (manual export), CV (AQU normalised format, 2024-12-31), ORCID `0000-0001-5338-3007` (public API), OpenAlex (public API, no key; paging via `page=`).

## Metrics (citations, quartiles, impact)
```bash
uv run _memory/tools/memory.py metrics            # Crossref + OpenAlex citations, OpenAlex journal indicators
uv run _memory/tools/memory.py sync --offline     # attach them to references.json and rebuild bib/index
```
- Citations: Crossref (`cited_by_crossref`), OpenAlex (`cited_by_openalex`), Scholar from the CV (`cited_by_scholar_cv_2024`, frozen at Dec 2024). Counts differ between sources; always show the source.
- Journal: OpenAlex `2yr_mean_citedness` (open proxy, **not** the Clarivate Impact Factor) and `h_index`.
- Quartiles: SCImago SJR. SCImago blocks automated downloads, so download the CSV manually (scimagojr.com → Journal Rankings → year → Download data) as `sources/scimago_<year>.csv`; `metrics` picks it up by ISSN.
- **Official indexing from the CV** (section K, the 10 most relevant contributions: JCR IF + quartile + categories, SJR, WoS/Scopus/Scholar citations, GGS conference rating, SPI for the book): extracted by `import-cv` into `sources/cv_quality.json` and attached to matching references as `indexing`. These are values **as reported in the CV (Dec 2024)**; the JCR year is not stated, so present them as such. Only covers 8 works.
- Official JCR Impact Factor/quartile for the rest is proprietary: enter it by hand in `overrides.json` if wanted (`"jcr_if"`, `"jcr_quartile"`).

## DOI as uniqueness and truthfulness key
```bash
uv run _memory/tools/memory.py doi              # verify every DOI against Crossref/DataCite, look up missing DOIs
uv run _memory/tools/memory.py sync --offline   # attach results, assign resolved DOIs, merge refs sharing a DOI
```
- Each reference gets `doi_check`: `verified` (registry title ≥0.9 similar, year ±1, X. Baró among the authors), `partial` (title matches but year/author differ: usually online-first vs issue year, or registry without authors), `mismatch`, `unresolved` (DOI not registered), `resolved` (DOI found by bibliographic search with high confidence; saved as `doi`, `doi_source: crossref-search`), `candidate` (possible DOI, needs review → `doi_candidate`), `none_found`.
- References that end up with the same DOI are merged (`merged_ids`). Preprint↔published pairs without a shared DOI are marked manually as `duplicate` in `overrides.json`.
- Results are cached in `sources/doi_check.json`; use `--refresh` to recheck everything.

## Portal de la Recerca de Catalunya (PRC)
https://portalrecerca.csuc.cat/orcid/0000-0001-5338-3007 (researcher `rp20011`, a single profile; no earlier profiles exist there).
`sync` / `portal` read the OpenSearch Atom feed (`open-search?query=author_authority:rp20011&format=atom`) and the theses tab. Each linked reference gets `repository_url` (institutional repository handle) and source `prc`; theses go to `theses.json`, not to `references.json`.
Beware: the portal also holds ~130 items by a homonym, **Xavier Baró Queralt** (historian). Never import by name, only by `author_authority:rp20011`. The theses tab sometimes returns empty: the script retries and keeps the previous theses on failure.
